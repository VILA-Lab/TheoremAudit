# Workflow

Run exactly one governed stage at a time. The controller stores artifacts under
`<workspace>/.theoremgate/runs/<run-id>/` and hashes every completed artifact.

Record the researcher's publication goal in the run contract at initialization. Treat it as an
optimization target for direction choice, theorem breadth, novelty evidence, experiments, and
writing—not as permission to weaken correctness. Contribution assessment must preserve the exact
goal. If submission evidence is incomplete, first run the eligible bounded contribution-
strengthening passes, then complete and write the strongest honest alternative when the route permits
it. Never open a publication-choice checkpoint.

Starting or resuming a run authorizes routine in-scope direction, salvage, strengthening, route, and
writing decisions. Do not ask for confirmation or approval at any stage. This autonomy does not
authorize a new topic, false evidence, or weaker correctness gates. When the goal cannot be met,
finish with the strongest supported narrower or null outcome.

After `governance_review`, any serious mathematical finding marked `repair_requested` automatically
enters `$proof-repair` for at most three same-run correction passes. Deferred, excluded, or invalidated
sibling closures retain their disposition and do not block repair of an independent closure. The
controller archives the failed pass and returns to discovery; the approved direction stays fixed and
a fresh audit is mandatory. When the correction
budget is exhausted, a finding is invalidated/deferred, or repair would materially change the
science, automatically salvage only independently supported proof closures or persist a null outcome.
Clear governance outcomes continue automatically.

At `theory_bundle`, derive the paper route before finalizing the bundle. When accepted mathematics
exists but the route does not satisfy an original-research or workshop goal, automatically enter
`$contribution-strengthening` for at most two same-run passes. Retry novelty alone when it is the
only failed gate; otherwise return to discovery to add one coherent theorem or method extension and
repeat all affected proof, audit, novelty, and significance stages. Preserve each assessed package
under `strengthening/round-XX/`. After the budget, finalize the strongest honest route without a
human publication decision.

| Stage | Required actor | Artifact | Role |
|---|---|---|---|
| `direction_generation` | `direction_generator` | `artifacts/directions.json` | Normalize one clear user direction, or generate alternatives for a vague/option-seeking request |
| `direction_selection` | `direction_selector` | `artifacts/selected_direction.json` | Audit and pass through one specified direction, or compare genuine alternatives |
| `discovery` | `discoverer` | `artifacts/discovery.json` | Fix setting, assumptions, targets, and proof DAG |
| `exploration` | `explorer` | `artifacts/exploration.json` | Probe special cases and recommend continue/narrow/reshape/block |
| `proof_development` | `proof_team` | `proofs/index.json` | Develop one run-scoped proof record for every obligation |
| `local_adversarial_audit` | `auditor` | `artifacts/local_audit.json` | Attack assumptions, proof gaps, boundaries, and counterexamples |
| `governance_review` | `governor` | `artifacts/governance_review.json` | Decide each major/fatal local finding |
| `theorem_synthesis` | `synthesizer` | `artifacts/synthesized_theorems.json` | State only what drafted proofs establish |
| `final_adversarial_audit` | `auditor` | `artifacts/final_audit.json` | Audit final statements against proofs and assumptions |
| `arbiter` | `governor` | `artifacts/arbiter.json` | Accept, weaken, request repair, mark conjectural, or reject |
| `novelty_audit` | `novelty_auditor` | `artifacts/novelty_audit.json` | Compare every accepted statement against verified closest work |
| `significance_audit` | `significance_reviewer` | `artifacts/significance_audit.json` | Audit technical depth, application evidence, operational assumptions, baselines, and significance |
| `contribution_assessment` | `contribution_developer` | `artifacts/contribution_assessment.json` | Classify contribution, significance, claims, and development needs |
| `theory_bundle` | `controller` | `artifacts/theory_bundle.json` | Export accepted theory and deterministically select the paper route |

The `theory_bundle` is generated by `complete`; do not write it manually.

Both adversarial audits require an externally anchored attack summary covering every in-scope proof
or statement, the prescribed attack families, and hash-bound evidence files. Use the packaged
revision command when a late finding changes the summary; direct JSON edits are invalid. Zero
findings is a valid outcome only after this attack record exists; an empty `findings` list by itself
is not an audit.

Before theorem synthesis, use the bounded same-run correction controller for repairable local proof
defects. It preserves the prior discovery, proofs, audit, governance decision, and manifest beneath
`corrections/round-XX/` before returning to discovery. Use a linked revision cycle with
`--parent-run` only for post-bundle mathematical changes, a materially new topic/contribution, or an
explicitly requested separate revision.

When bounded correction cannot recover the result, synthesize only independently supported proof
closures and otherwise preserve a null outcome. Do not wait for a user decision. `based_on` is
research provenance; only `synthesized_from`, its transitive proof dependencies, and the assumption
closure propagate correctness blockers.
